# SOLVE 官方数据结构规格（草案 v1）

更新日期 2026-11-08。本文记录用户与 Claude 讨论确认的官方数据结构，以及它要求引擎和前端新增的能力。引擎部分已在 `claude/dev` 分支实现并通过实机验收（第 11 节）；前端（状态栏、调试面板、结构制作面板）尚未实现。

## 1. 定位

- 官方数据结构**面向玩家**：给没有自带变量的角色卡补上一套开箱即用的变量，同时作为示例。
- 数据结构作者可以拿它修改成自己的结构，但官方结构不为作者的写法做迁就，也不要求作者照它来写。
- 状态栏能渲染**任何符合标准的结构**，不只是官方结构。标准、渲染与布局声明见第 8 节。

## 2. 设计原则

1. **键名统一英文**，显示名由结构描述提供。枚举值暂用中文（模型直接用故事语言填写）。
2. **核心 + 模块**：核心不可关闭；其他内容是模块，玩家可开关。关闭的模块字段休眠，不进提示词，重新开启时数据还在。
3. **由操作 LLM 推断**：位阶、特殊属性、货币种类等依世界观决定的内容都是自由文字或开放字典，由操作 LLM 自行推断，不要求玩家预先配置。
4. **一处事实**：同一件事只记一处。在场只记在 `meta.present`，用户角色只由 `role` 表达。
5. **空缺不是 0**：属性等数值字段可为 `null`，表示该角色没有这项（例如亡灵没有体质）。状态栏显示为「—」。
6. **剧透等级**（前端能力）：每个字段有「公开 / 剧透 / 隐藏」三级。剧透字段在状态栏模糊显示、点击查看；隐藏字段只在调试面板可见。默认等级见各表，玩家可在设置里调整。模型照常看到这些字段，剧透等级只影响玩家界面。

## 3. 核心（不可关闭）

### 3.1 `meta`

| 键 | 名称 | 类型 | 约束与说明 |
| --- | --- | --- | --- |
| `round` | 轮次 | 整数，只读 | 引擎维护，见 6.6。用作事件和记忆的时间戳 |
| `time.era` | 纪元 | 文字 | |
| `time.year` / `month` / `day` | 年 / 月 / 日 | 整数 | 月、日范围不固定（架空历法），只校验为整数 |
| `time.clock` | 时分 | 文字 | 格式 `HH:MM` |
| `location` | 当前地点 | 引用 → `places`，可为空 | 地点实体始终可用，见 5.1 |
| `weather` | 天气 | 枚举 | 晴/雨/阴/雪/雾/大风/雷暴/暴雨/沙暴/瘴气/异象 |
| `present` | 在场角色 | 引用数组 → `characters` | 删除角色时自动移除 |
| `mood` | 场景情绪 | 枚举 | 日常/紧张/战斗/悲伤/浪漫/神秘/欢快/恐怖，用于选曲（6.9） |

推进时间时，模型用 `$set` 整体写入 `time`，引擎不做分钟进位。

### 3.2 `characters.<charId>` 核心字段

角色是实体集合，键就是角色 ID。

| 键 | 名称 | 类型 | 说明 |
| --- | --- | --- | --- |
| `name` | 姓名 | 文字 | |
| `alias` | 别称 | 文字，可选 | |
| `thumb` / `image` | 缩略图 / 立绘 | 网址，可选 | 每个实体两张图：缩略图用于头像（横条、人物卡、关系图节点、图鉴列表），立绘用于大图展示（角色页顶部、人物卡展开后、图鉴详情，点击可全屏查看）。只填一张时另一处用这张；都没有或加载失败时显示首字。缩略图可以带媒体片段 `#xywh=percent:x,y,w,h`，从大图里裁出一块正方形（例如脸部），不必另外托管小图。媒体字段不进入给模型的两种视图（`readonly` + `internal`），由作者或玩家填写 |
| `role` | 定位 | 枚举 | 用户角色/核心角色/主要配角/次要配角/一次性敌人。「一次性敌人」给只出场一次的敌人（拦路强盗、一场战斗的怪物），事件结束后删除；会反复出场的反派按分量归入配角。路人、龙套不建立角色实体（写进指南） |
| `origin` | 原型 | 文字，可选 | 用 `$from` 以模板或预制人物为基础生成时，写来源的 ID（模板数据里可以直接带上）。图鉴据此列出「由此生成」 |
| `age` | 年龄 | 文字 | 例如「外表十八，实际千岁」 |
| `intro` | 简介 | 文字 | 背景与人设概括 |
| `tags` | 身份 | 文字数组 | 清单上限，见 6.4 |
| `appearance` | 外貌 | 文字 | |
| `condition` | 当前状态 | 文字 | 叙事性描述，例如「疲惫，左臂受伤」。数值类状态放在 `rp.gauges` |

## 4. 角色模块（挂在 `characters.<charId>` 下）

### 4.1 驱动力 `drive`

| 键 | 名称 | 类型 | 剧透 |
| --- | --- | --- | --- |
| `goals.long` / `goals.short` | 远期 / 近期目标 | 文字 | NPC 默认剧透 |
| `thoughts` | 想法 | 文字 | NPC 默认剧透 |
| `plan` | 规划 | `[{ text, done }]`，清单上限 | NPC 默认剧透 |

用户角色的这些字段默认公开。

### 4.2 社交 `relations.<charId>`

键是对方的角色 ID（引用，对方被删除时整条移除）。关系是单向的：A 对 B 的看法记在 A 身上。

| 键 | 名称 | 类型 | 说明 |
| --- | --- | --- | --- |
| `affection` | 好感度 | 整数 −100～100 | 单次变化上限 ±10（6.3） |
| `labels` | 关系 | 文字数组，清单上限 | |
| `impression` | 印象 | 文字 | |
| `promises` | 约定 | 文字数组，清单上限 | |
| `keyEvents` | 关键事件 | `[{ round, text }]`，清单上限 | `round` 由引擎自动填写（6.6） |

### 4.3 角色扮演 `rp`

| 键 | 名称 | 类型 | 子模块 |
| --- | --- | --- | --- |
| `rank` | 位阶 | 文字 | 由操作 LLM 依世界观推断 |
| `attributes` | 属性 | 见 4.4，四种体系互斥 | 属性 |
| `special` | 特殊属性 | 字典 `名称 → 文字、数字或 { value, max }` | 属性 |
| `abilities` | 能力 | 引用字典 `能力 ID → { level?, progress? }` | 能力。能力本体在根节点 `abilities`（见 5.4），这里只写本人的等级与熟练度（0～100，锻炼和实战让它增长，满 100 等级加一并归零）；多人共有同一能力时引用同一个 ID |
| `gauges` / `gaugesText` | 量表 | 字典 `名称 → { value, max }`（数值）或 `名称 → 一句描述`（描述） | 状态；两种写法由互斥组「量表与熟练度」决定 |
| `effects` | 效果 | 字典 `名称 → { desc, source?, until? }` | 状态 |

- 量表的名称与数量由模型依世界观和剧情决定（生命、体力、法力、理智……）。**互斥组「量表与熟练度」**（`scales`）二选一：「数值」（`scale_num`，默认）写 `rp.gauges.<名称> = { value, max }`、能力熟练度写 `progress`（0～100），状态栏画成进度条；「描述」（`scale_text`）写 `rp.gaugesText.<名称> = 一句话`（如「伤口在渗血，勉强能走」）、熟练度写 `progressText`，更贴剧情。玩家随时切换，和属性体系一样，引擎把原来的数据附在一次性的迁移指令里交给模型换算。
- `effects` 不计剩余回合。`until` 是可选的文字条件（例如「直到天亮」），模型判断剧情上结束后移除。

### 4.4 属性体系（互斥组 `attributes`）

四种体系是一个**互斥组**（6.2）：玩家随时切换，同一时间只有一种开启；其余休眠，数据保留，LLM 看不到。所有属性都允许 `null`（空缺）。

| 体系 | 键 | 值 | 状态栏 |
| --- | --- | --- | --- |
| `dnd` | `str dex con int wis cha` | 整数 0～30 或空缺；调整值 ⌊(值−10)/2⌋ 由引擎计算 | 数字 + 调整值小标 |
| `wod` | 生理 `str dex sta`，心智 `int wits res`，互动 `pre man com` | 整数 ≥0，无上限，或空缺；**超凡** = 值≥1 时 ⌊(值−1)/5⌋，由引擎计算，模型可见、不可写 | 数字 + 超凡徽章 + 5 格进度（距下一点超凡） |
| `fate` | `physique athletics melee shoot notice empathy rapport deceive provoke contacts investigate lore crafts burglary stealth drive resources will` | 阶梯 F/F+/E/E+/D/D+/C/C+/B/B+/A/A+/S/S+/EX 或空缺 | 阶梯 |
| `fu` | `might dex insight will` | 弱/普通/优秀/卓越 或空缺（对应原规则 d6/d8/d10/d12，只在提示框显示） | 四格阶梯 |

WOD 兼容「无限恐怖」类规则：中后期一项属性可达几十点，因此只显示数字，不用圆点。超凡示例：5→0，6→1，10→1，11→2。

### 4.5 资产

| 键 | 名称 | 类型 | 说明 |
| --- | --- | --- | --- |
| `items` | 物品 | 引用字典 `物品 ID → { count, equipped, stored?, note? }` | 物品本体在根节点 `items`（见 5.4），这里只写本人的数量（`count`，随身携带的部分）、是否装备、存放在建筑里的数量（`stored`：`建筑 ID → 数量`，属于建筑模块）和一句备注。独一无二的物品（`unique: true`）同一时间只能在一个角色名下：加到新持有者名下时，引擎自动从原持有者处移除（也可以用 `$move`）；普通物品可多人各自持有并各记数量 |

**钱是物品**：类型为「货币」的物品（币种依世界观：金币/银币/铜币、文/银两、美元/人民币/日元……），各建一个物品实体，持有者用 `count` 记数量。付钱、交易用 `$transfer` 在双方的 `count` 之间转移；对方还没有这种货币时，`$transfer` 会按结构新建这一条（其他字段取默认值），总数守恒。说不清数额时在 `note` 写描述（如「一小袋碎银」）。状态栏的背包把货币单独列一组，角色卡顶部也显示随身的钱；内置常见货币图标：金币、银币、铜币、文、银两、美元、人民币、日元，其他名称显示通用硬币。（原先的 `funds` 字段已取消。）

## 5. 根节点模块

### 5.1 地图 `places.<placeId>`（节点地图）

不做网格地图。地点是实体集合，用层级和连通两种关系组成节点图。

实现时调整：`meta.location` 必须引用一个地点实体，所以 `places` 本身放在核心里（不可关闭）；「地图」模块只控制节点图特有的 `links` 与 `discovered`。关闭地图模块时仍然有地点和层级路径，只是没有连通关系与探索状态。

| 键 | 名称 | 类型 | 说明 |
| --- | --- | --- | --- |
| `name` | 地点名 | 文字 | |
| `kind` | 类别 | 枚举 | 区域/地点 |
| `parent` | 所属区域 | 引用 → `places`，可选 | 例：世界 → 王都 → 酒馆 |
| `links` | 相连 | 引用数组 → `places` | 只记相通关系，不需要坐标 |
| `desc` / `truth` | 描述 / 真实描述 | 文字 | `truth` 默认隐藏 |
| `discovered` | 已发现 | 布尔 | 未发现的地点在地图上雾化 |
| `thumb` / `image` / `bgm` | 缩略图 / 背景图 / 背景音乐 | 文字（网址或曲库标识），可选 | 地图节点用缩略图（没有则用背景图）做小圆图，详情卡顶部显示场景图并写出当前配乐（没有自己的配乐时注明沿用哪个区域）。不进入给模型的视图 |

状态栏（电脑与手机都用节点图）：自动排版，当前位置高亮并居中，双指缩放、拖曳平移，点击节点打开详情（手机为底部抽屉）。顶部显示层级路径「王都 › 酒馆」。

区域与地点：下面挂着地点的地点（区域）不画成节点，而是画成一片包住它所有下属地点的底色范围，区域名写在范围上缘；同一区域的地点在排版时互相靠拢，嵌套的区域外层范围更宽。当前位置所在的区域颜色更深。点区域名选中整个区域（详情卡列出区域内的地点），拖动区域名可整体移动。区域之间（或地点与别的区域）的「相连」从区域中心画出，只露出范围之间的一段；地点与自己所属区域的相连不再画。没有下属地点的区域仍画成节点。

### 5.2 建筑 `buildings.<buildingId>`（原「不动产」）

住宅、商铺，以及银行、出租仓库这类替任何人保管东西的地方。

| 键 | 名称 | 类型 |
| --- | --- | --- |
| `name` | 名称 | 文字 |
| `kind` | 类别 | 枚举：住宅 / 商铺 / 银行 / 仓库 / 据点 / 其他 |
| `owner` | 产权人 | 引用 → `characters` 或 `factions` |
| `place` | 位置 | 引用 → `places` |
| `vault` | 可寄存 | 开关：任何人都能把东西存进来（银行、出租仓库） |
| `thumb` / `image` | 缩略图 / 图片 | 媒体链接 |
| `desc` / `truth` | 描述 / 真实描述 | 文字 |
| `developments` | 建设 | 字典 `名称 → 文字` |

存放的东西仍记在持有者自己名下：`characters.<id>.items.<物品ID>.stored.<建筑ID>` 是数量，`count` 只算随身的。存取就是在 `count` 与 `stored` 之间 `$transfer`；建筑被删除时，各人在那里的存放条目随之移除。状态栏背包按建筑分组列出「存放于 ×××」，建筑页签的卡片列出存在里面的物品和主人。

### 5.4 物品与能力 `items` / `abilities`（实例）

物品和能力都是实例：本体只在根节点存一份，角色那边只是引用（以 ID 为键），附上本人才有的状态。引用必须指向存在的同类实体；删除实例时，所有持有者的引用自动清理。

| 键 | 名称 | 类型 | 说明 |
| --- | --- | --- | --- |
| `items.<itemId>` | 物品 | 实体集合 | `name`、`type`（装备/道具/消耗/货币/关键/杂物/座驾）、`unique`（独一无二）、`thumb?` / `image?`（缩略图 / 图片，同角色的两张图规则，不进入给模型的视图）、`desc`、`truth?`（默认隐藏）、`condition?`（主要给座驾用） |
| `abilities.<abilityId>` | 能力 | 实体集合 | `name`、`kind`（特质/技能）、`desc`、`truth?`、`levels`（等级效果） |

`levels` 以等级数字为键写每一级的效果，例如 `{ "1": "推开一名敌人", "3": "可以把目标撞倒", "5": "波及两名敌人" }`。可以跳级：持有者按不超过自身 `level` 的最高一级生效。能力页显示本级效果与下一级（变淡）；图鉴显示完整的等级表，并在每一级上标出处于这一级的角色。

状态栏的「图鉴」页签按物品 / 能力分类浏览这些实例，可搜索、按类型筛选，详情里列出所有持有者。

### 5.5 预制人物与模板

SOLVE 引擎本来就有两种现成实体，由世界书 `[SOLVE:PREFABS]` / `[SOLVE:TEMPLATES]`（或结构描述的 `prefabs` / `templates`）提供，格式都是 `ID → { type, data }`：

| | 预制实体 prefab | 模板 template |
| --- | --- | --- |
| 用途 | 设计好的具体人物：一次性敌人（墓园猎犬），或会反复出场、提前写好的反派（余烬主教） | 一类人物的底稿（教团狂信徒），可以生成任意多个 |
| 登场 | `$createEntity: { "characters.@grave_hound": {} }`，以它自己的 ID 登场，数据自动带入 | `$createEntity: { "characters.@one_eye": { "$from": "@cult_zealot", "name": "独眼狂信徒" } }` |
| 次数 | 只能登场一次（未登场 → 已登场 → 已退场，删除后不能复活） | 不限 |

另外，`$from` 也可以指向预制实体：以它为基础生成一个不同 ID 的独立角色，预制本身的状态不变。

给模型的指南里，引擎自动列出尚未登场的预制实体和全部模板（ID 与名称），已登场、已退场的不再列出。

状态栏「图鉴 → 角色」常态列出类型为 `character` 的模板；预制实体收进底部默认折叠的「预制角色」分组（标题显示已登场 / 未登场 / 已退场的数量，搜索命中时自动展开）。已登场的显示此刻状态并可跳到角色卡；未登场的资料默认收起（点一下查看）；详情列出 `origin` 指向它的角色（由此生成）。

投影：只有在场角色持有或掌握的物品、能力完整交给模型，其余只留名称与类别（规则 `kind: 'referenced'`），模型仍知道已有哪些 ID，不会重复建。

### 5.6 设定 `lore.<loreId>`（模块「设定」）

剧情中确立下来的设定：世界观、历史、规则、秘密、伏笔、传闻、主线。卡作者写好的固定设定仍放在世界书，这里只记玩的过程中新确立的。

| 键 | 名称 | 类型 | 说明 |
| --- | --- | --- | --- |
| `title` | 标题 | 文字 | 必填 |
| `kind` | 类别 | 枚举：世界观 / 历史 / 规则 / 秘密 / 伏笔 / 传闻 / 主线 | |
| `content` | 内容 | 文字（段落） | 一两句 |
| `truth` | 真相 | 文字，可省略 | 玩家看不到（hidden） |
| `known` | 主角已知 | 开关，默认是 | 否时整条在状态栏里是剧透（列表里标题显示为 ？？？） |
| `stage` | 进度 | 枚举：未展开 / 进行中 / 已收束，可空 | 伏笔与主线用 |
| `related` | 相关 | 引用列表 → 角色、地点、势力、物品、建筑 | 这些实体的卡片底部列出相关设定 |
| `source` | 来源 | 枚举：剧情 / 玩家 | 玩家写的设定模型必须遵守 |

给模型的方式从简：全部条目原样提供，不做关键词或相关度筛选；上限 40 条（32 条起提示合并）。状态栏有「设定」页签（可搜索），玩家可以「写一条设定」（提交后下一轮告诉模型），也可以修改、撤回自己写的设定；剧情确立的设定玩家只能看。

## 6. 需要新增的引擎能力

| # | 能力 | 说明 |
| --- | --- | --- |
| 6.1 | 声明式结构描述 | JSON 描述字段类型、约束、显示名、剧透等级和布局，编译成现有定义（Zod + 实体/引用/模块/指南）。制作面板编辑的就是这份描述 |
| 6.2 | 互斥组与迁移指令 | **通用能力**：任何一组模块都可以声明为互斥。切换时关闭其他成员，数据保留休眠。切换那一次，引擎给操作 LLM 一条一次性迁移指令，附上切出成员的当前数据，要求按新成员的规则换算填写；之后旧数据不再进入提示词 |
| 6.3 | 单次变化上限 | 字段可声明 `maxDelta`，超出时截断并给模型反馈。只作用于声明的字段；官方结构只给好感度和声望设 ±10，玩家可在设置里调整 |
| 6.4 | 清单上限与预警 | 每个会增长的清单有「上限」和「预警线」，玩家在设置里调整（按聊天保存，另有全局默认）。到预警线时，给操作 LLM 的指令自动加上「X 清单已有 n/m 条，请合并相近条目、删除过时内容」；到上限时拒绝新增并反馈 |
| 6.5 | 计算字段 | 由其他字段算出、不存储、模型不可写，但进入投影（WOD 超凡、DND 调整值） |
| 6.6 | 轮次 | `meta.round` = 该次模型回复所在的酒馆楼层号；保险规则：不小于上一提交的轮次 + 1（防止用 `/cut` 删中间楼层后编号回退）。切换回复版本、重新生成不改变轮次。`keyEvents` 等条目的 `round` 在写入时由引擎自动填写 |
| 6.7 | 声明式投影 | 默认规则：在场角色输出全部字段；不在场角色只输出核心字段；社交只输出与用户角色和在场角色有关的条目；地点只输出当前位置、上级路径与相邻地点的全部字段，其余只输出名称 |
| 6.8 | 剧透等级 | 前端能力，按字段读取等级，模型侧不受影响 |
| 6.9 | 背景音乐 | 引擎负责播放。曲库由卡作者附带和玩家自行添加，两者都支持，每首标注情绪。选曲顺序：当前地点 `bgm` → 上级区域 `bgm` → 曲库中符合 `meta.mood` 的曲目。换曲淡入淡出；播放、暂停、音量在状态栏，设置存在玩家本机；浏览器要求首次播放前用户点击一次页面 |

## 8. 渲染标准与前端分工

- **行为**：Radix 无头组件（页签、折叠、进度条、提示框、滚动区等）。
- **样式**：有卡密预设时沿用卡密的皮肤（SOLVE 组件输出相同的 `data-k` / `data-k-part` 钩子，读取 `--k-*` 令牌）；独立运行时用 SOLVE 自带的默认皮肤。SOLVE 不复制卡密预设的代码（卡密预设为 CC BY-NC 4.0，SOLVE 为 AGPL-3.0）。样式钩子不够用时，向卡密预设仓库提 issue。
- **布局**：由结构作者声明（页签、分组、列数、顺序、折叠）。单个字段的控件默认按类型推断，可用 `as` 在固定清单内改写。未写进布局的字段归入「其他」区。
- **不渲染**：结构可声明 `render: false` 整体关闭自动渲染，或在某一区块声明 `render: false` 留出挂载点，由作者自行渲染；SOLVE 照常提供数据和接口。

前端分三部分：按结构渲染的状态栏、调试面板、结构制作与修改面板。现有调试工作台将整体重做。实现前先出风格与布局预览，经用户确认后再实施。

### 11.3 结构描述格式

结构描述是可 JSON 序列化的对象：`{ id, version, label?, fields, modules?, groups?, round?, projection?, guide?, guides?, initialData?, prefabs?, templates?, display?, bgm? }`。`prefabs` / `templates` 原样进入定义（与世界书 `[SOLVE:PREFABS]` / `[SOLVE:TEMPLATES]` 相同）。`fields` 中每个字段：

| 属性 | 含义 |
| --- | --- |
| `type` | `object` / `record` / `array` / `string` / `int` / `number` / `bool` / `enum` / `ladder` / `ref` / `refs` / `oneOf` |
| `variants` | `oneOf` 接受的几种形式（至少两种，JSON 类型各不相同，不能是引用），例如 `[{ type: 'object', fields: { value, max } }, { type: 'string' }]`。数值形式里的字段照常可增减、截断 |
| `fields` / `of` | 对象的子字段；字典值、数组元素的结构 |
| `entity` | 字典是实体集合，值为实体类型 |
| `keys` | 字典的键是指向该类型实体的引用（目标删除时整条移除） |
| `uniqueBy` | 与 `keys` 合用：目标实体的这个布尔字段为真时，它同一时间只能出现在一个这样的字典里。加到新字典时引擎自动从旧字典移除并给 L1 反馈（`UNIQUE_MOVED`）；一条语句同时放进两处、或把已被多人持有的实体改成独一无二，会被拒绝（`UNIQUE_HELD`）。编译为定义的 `uniqueHolds`，计入指纹 |
| `values` | 枚举值；`ladder` 是有序枚举（由低到高） |
| `to` | `ref`/`refs` 的目标实体类型（可为数组），编译后自动校验类型 |
| `min` `max` `maxDelta` | 数值约束；单次变化上限 |
| `required` `optional` `nullable` `default` | 必填、可省略、可为空缺、默认值。未写时自动给默认值（文字 `''`、数值 0 或下限、枚举第一项、容器为空） |
| `module` | 字段归属的模块（模块在 `modules` 中声明，可有 `parent`、`exclusive`）。可写数组：所有列出的模块都开启时字段才生效（如量表同时属于「状态」和「数值」） |
| `list` | `{max, warn}` 清单上限与整理预警线 |
| `computed` | `[{label, formula}]`，内置公式 `wodTranscend`、`dndModifier` |
| `stamp` | 数组元素为 `{round, text}`，引擎自动填写轮次；模型可以直接写字符串 |
| `sections` | 对象子字段的展示分组 `[{ label, keys }]`（只影响前端，不进入指纹）。官方结构：WOD 分 身体 / 心智 / 社交，DND 分 身体 / 心智 |
| `label` `desc` `spoiler` `as` | 显示名、说明、剧透等级、控件覆写（只影响前端，不进入定义指纹）。剧透等级按路径取最深一层的声明：剧透字典里的某个字段可以声明 `public`（如好感度），`hidden` 不能被下层解除 |
| `create` | 值为对象的字典：状态栏在列表上方给出「新增」表单 `{ label, fields, set?, narrate? }`——`fields` 是表单里填的字段，`set` 是每条固定写入的值（如 `source: '玩家'`），新条目自动取 ID。见 §11.6 |
| `reveal` | 带剧透等级的字典：满足这个条件的条目照样公开（官方结构：别人身上 `equipped: true` 的物品看得见）。条件写法同交互的 `when` |
| `readonly` `internal` | 沿用 SOLVE 原有的提示词可见性 |
| `edit` | 玩家可在状态栏原地修改这个值（`true` 或 `{ owner?: 'user', narrate? }`），控件按类型推断：文字 / 段落 / 数字 / 开关 / 枚举。见 §11.6 |
| `actions` | 状态栏上的动作按钮。写在 `record` / `array` 上作用于每一项，写在 `object` 上作用于它本身。见 §11.6 |

`display`（布局、渲染开关等）和 `bgm` 只影响前端与播放，不进入定义指纹：修改它们不会让旧聊天失配。

`display` 由结构作者声明状态栏的布局（渲染组件只认这些声明，不认具体字段名）：

| 键 | 含义 |
| --- | --- |
| `bar` | 悬浮概览横条显示的字段路径（也是展开后面板的标题栏），可用 `$user` 指玩家角色。官方结构为 地点 · 时间 · 天气 · 场景情绪 · 在场角色；手机上只保留地点、时间、天气。横条的位置由宿主按设备（电脑 / 手机）记住，收起、展开、刷新后都不变 |
| `layout` | 面板页签：`{ tab, module?, items }`。`items` 可用：`{ sheet }` 玩家角色卡（`subtitle/badges/tags/vitals/status/effects/currency/pages` 指定各区域对应的字段）；`{ graph }` 关系图（`edges/weight/label/tone/tones/size/present/legend`，默认折叠）；`{ list }` 折叠卡片列表（`exclude: '$user'`、`present`、`order`、`badges`、`score`、`search`（搜索名字、别称、身份）、`aside: { label, paths }`（概况：电脑上放在立绘下方的左栏，手机上作为第一页）、`backrefs: [{ collection, field, label }]`（卡片底部列出引用了它的条目，如相关设定）；`pages` 把展开后的卡片分成小页签，`relations.$user` 这类「以玩家为键」的条目显示为醒目的「对你」块，`as: 'quests'` 显示为任务日志，`as: 'inventory'` 显示为背包）；`{ map }` 力导向地图（`current/parent/links/discovered`；有下属地点的区域画成包住地点的范围）；`{ codex: [...] }` 图鉴，两种分类：`{ collection, label, group?, holders }` 浏览根节点实例（搜索、按 `group` 字段筛选），详情列出所有持有者及其本人状态（`holders` 为 `characters.*.items` 这类路径模式），能力详情附等级表，背包与能力页可一键跳到图鉴；`{ prefabs: 'character', into: 'characters', label, origin?, badges?, pages? }` 常态列出该类型的模板，预制实体收进默认折叠的分组，`pages` 同 `list` |
| `spoilerExempt` | 不受剧透遮挡的实体（官方结构：玩家角色） |


### 11.4 新增的控制器与全局接口

| 接口 | 作用 |
| --- | --- |
| `SOLVE.controller.setSettings({ lists?, maxDelta? })` | 玩家设置清单上限/预警线与单次变化上限；值为 `null` 恢复默认，`maxDelta` 为 0 表示不限。作为玩家动作保存，重放结果一致 |
| `SOLVE.controller.getSettings()` | 当前设置与默认值 |
| `SOLVE.controller.getComputed()` | 全部计算值（按 JSON 指针），给状态栏用 |
| `SOLVE.controller.getDisplay()` | 显示名、剧透等级、控件、布局 |
| `SOLVE.controller.getMigration()` | 待发送的迁移指令（没有时为 `undefined`） |
| `SOLVE.bgm.status()` / `setEnabled()` / `setVolume()` / `addTracks()` / `removeTrack()` / `subscribe()` | 背景音乐状态与玩家曲库（存于本机浏览器） |

### 11.5 行为细节

- **轮次**：模型回复提交时，引擎把「该回复所在楼层号」与「上一提交轮次 + 1」取较大值，记入该动作（`authorInputs.solveRound`），因此重放、恢复结果一致。没有操作块的回复也会推进轮次。玩家手动操作不推进轮次，可以手动修正它。
- **互斥组**：开启组内一个成员时自动关闭其他成员，数据保留。迁移指令记在引擎状态里，下一次模型动作执行后清除；连续切换保留最初的来源，切回来源则取消迁移。组可声明 `migrate: false` 关闭迁移指令。
- **清单**：到上限时只拒绝「增加」，玩家把上限调低不会让已有状态报错，删除和整理照常可用。
- **引用类型**：实体 ID 全局唯一（角色、物品、地点、势力之间也不能重名）；编译后的定义会校验每个引用指向声明的实体类型。
- **存储**：楼层格式仍为 3。新增的玩家设置动作保存为 `{actionId, settings}`；引擎状态里的 `settings`、`migration` 只在使用时出现，旧状态的哈希不变。旧版引擎读不了含设置动作的聊天。

### 11.6 玩家交互（`edit` / `actions`）

和渲染一样，交互只靠结构声明：状态栏读编译后 `display.fields[路径].edit / .actions` 自动生成按钮和编辑器，宿主没有提供交互接口时一律只读，图鉴始终只读。实现在 `src/interact.ts`（声明校验、模板填充、条件）与 `src/ui/statusbar/interact.tsx`（按钮、询问、原地编辑、撤销提示、待告知清单）。

**字段可编辑** `edit: true | { owner?: 'user', when?, narrate? }`：`when` 是所在对象要满足的条件（如只有玩家写的设定可改：`{ source: '玩家' }`）。写在 `{text, done}` 清单（数组）上时，玩家可以改写、删除、添加条目（整份清单一次 `$set`）；写在清单元素的 `done` 上时可以勾选。`owner: 'user'` 只在玩家角色名下开放；`narrate` 是告诉模型的一句话（bool 可写两句：[变为真, 变为假]），不写就是静默修正——模型下一轮只会看到新状态。占位符有 `{value}` `{old}` `{label}`，以及同一对象的其他字段（如规划的 `{text}`）。

**动作** `actions: { 名字: { label, toggle | ops, when?, owner?, ask?, confirm?, narrate?, tone? } }`：

| 键 | 含义 |
| --- | --- |
| `label` | 按钮文字；`toggle` 动作写两句 [打开, 关闭] |
| `toggle` | 简写：翻转该项的一个布尔字段（如 `equipped`） |
| `ops` | 普通 SOLVE 操作，可用占位符；`{ $if: 条件, then: [...], else: [...] }` 按条件选操作（条件按执行前的状态判断）。空数组表示只告诉模型、不改数据（能力的使用 / 锻炼 / 开发） |
| `when` | 显示条件：键是该项字段（引用型条目会合并被引用实体的字段，如持有物品的 `type`、`unique`），`@路径` 读绝对路径；值是相等或 `{eq, ne, gt, gte, lt, lte, in, exists, empty}`（`empty`：缺失、空字符串、0、空数组或空对象） |
| `owner` | `user`：只出现在玩家角色名下的条目上 |
| `ask` | 执行前询问，按声明顺序（后面的可以用前面的答案）：`{ label, pick: 路径, within?, not?, filter? }` 选一项——`pick` 可以是实体集合（`characters`）或带占位符的引用字典（`{self}.stored`），`filter` 是条件数组、满足任一即可选（如 `[{ owner: '{holderId}' }, { vault: true }]`）；选中后可用 `{键}`、`{键.name}`、`{键.value}`（引用字典里那一项的值）；`{ label, number: { min, max, default } }` 填数量（可用占位符，如 `max: '{from.value}'`）；`{ label, text: { placeholder?, optional? } }` 写一句话。可带 `when`，不满足时直接用默认值 |
| `module` | 只在这个模块开启时显示（如存取需要 `buildings`） |
| `confirm` | 先确认（破坏性操作） |
| `narrate` | 告诉模型的一句话 |
| `tone` | `danger`：按钮用警示色 |

占位符：`{self}` 该项路径、`{id}`、`{name}`、`{holder}` / `{holderId}`（所在实体）、`{user}` / `{userId}`、该项的字段（`{count}`）、询问的答案（`{to}`、`{to.name}`、`{n}`）。整串只有 `{x}` 或 `-{x}` 时保留原类型（数字仍是数字）。

**执行**：填好的操作整组提交（`$group`，要么全部生效要么全部撤回），来源为 `user`，引擎照常校验 Schema、上下限与独一无二物品；被拒绝时按钮下方显示原因，不落库。成功后弹出提示，可撤销最新一笔；带 `narrate` 的操作进入「下一轮告诉模型」清单（面板底部可展开），下一次生成时注入提示词后清空。模型生成期间交互暂停（宿主传入 `locked`）。

**官方结构的默认声明**（物品、能力、驱动力只在玩家角色名下开放）：

| 对象 | 交互 |
| --- | --- |
| 物品 | 装备 / 卸下（类型「装备」）、使用（类型「消耗」，数量减一，用完移除）、交给…（从在场角色里选人，可选数量；钱也这样付；独一无二的物品整件转手）、存入…（存进自己的建筑或可寄存的建筑，全部存起来的装备自动卸下）、取出…（从存放的建筑取回）、丢弃（需确认，只丢随身的部分）。存取需要建筑模块开启 |
| 能力 | 使用（技能；可写怎么用、对谁用）、锻炼（可写怎么练）、开发（必须写想开发什么）：只告诉模型，结果由模型叙述并调整熟练度 / 等级，或补充等级效果、新建衍生能力 |
| 驱动力 | 远期 / 近期目标、想法可原地修改；规划可勾选完成（告诉模型）、改写、删除、添加（静默） |
| 档案 | 简介、外貌可原地修改（静默） |
| 地点 | 前往这里（设为当前地点） |

**宿主接口**（`StatusBar` 的 `interact` 属性）：`run({ ops, title, narrate? }) → { ok } | { ok: false, error }`（`ops` 为空时只记下 narrate）、`undo?() → boolean`、`locked?`、`pending?`（待告知清单）。酒馆宿主的接入（经 `submitUser` 提交、注入提示词、撤销）尚未实现，目前只有设计预览接上了真引擎。
