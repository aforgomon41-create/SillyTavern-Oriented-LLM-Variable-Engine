# SOLVE 官方数据结构规格（草案 v1）

更新日期 2026-11-08。本文记录用户与 Claude 讨论确认的官方数据结构，以及它要求引擎和前端新增的能力。目前只是规格，尚未实现；实现进度另见 [当前实施状态](implementation-status.md)。

## 1. 定位

- 官方数据结构**面向玩家**：给没有自带变量的角色卡补上一套开箱即用的变量，同时作为示例。
- 数据结构作者可以拿它修改成自己的结构，但官方结构不为作者的写法做迁就，也不要求作者照它来写。
- 状态栏能渲染**任何符合标准的结构**，不只是官方结构。标准、渲染与布局声明见第 8 节。

## 2. 设计原则

1. **键名统一英文**，显示名由结构描述提供。枚举值暂用中文（模型直接用故事语言填写）。
2. **核心 + 模块**：核心不可关闭；其他内容是模块，玩家可开关。关闭的模块字段休眠，不进提示词，重新开启时数据还在。
3. **由操作 LLM 推断**：位阶、特殊属性、货币种类等依世界观决定的内容都是自由文字或开放字典，由操作 LLM 自行推断，不要求玩家预先配置。
4. **一处事实**：同一件事只记一处。在场只记在 `meta.present`，用户角色只由 `role` 表达。
5. **空缺不是 0**：属性等数值字段可为 `null`，表示该角色没有这项（例如亡灵没有体质）。状态栏显示为「—」。
6. **剧透等级**（前端能力）：每个字段有「公开 / 剧透 / 隐藏」三级。剧透字段在状态栏模糊显示、点击查看；隐藏字段只在调试面板可见。默认等级见各表，玩家可在设置里调整。模型照常看到这些字段，剧透等级只影响玩家界面。

## 3. 核心（不可关闭）

### 3.1 `meta`

| 键 | 名称 | 类型 | 约束与说明 |
| --- | --- | --- | --- |
| `round` | 轮次 | 整数，只读 | 引擎维护，见 6.6。用作事件和记忆的时间戳 |
| `time.era` | 纪元 | 文字 | |
| `time.year` / `month` / `day` | 年 / 月 / 日 | 整数 | 月、日范围不固定（架空历法），只校验为整数 |
| `time.clock` | 时分 | 文字 | 格式 `HH:MM` |
| `location` | 当前地点 | 引用 → `places` | 地图模块关闭时为文字 |
| `weather` | 天气 | 枚举 | 晴/雨/阴/雪/雾/大风/雷暴/暴雨/沙暴/瘴气/异象 |
| `present` | 在场角色 | 引用数组 → `characters` | 删除角色时自动移除 |
| `mood` | 场景情绪 | 枚举 | 日常/紧张/战斗/悲伤/浪漫/神秘/欢快/恐怖，用于选曲（6.9） |

推进时间时，模型用 `$set` 整体写入 `time`，引擎不做分钟进位。

### 3.2 `characters.<charId>` 核心字段

角色是实体集合，键就是角色 ID。

| 键 | 名称 | 类型 | 说明 |
| --- | --- | --- | --- |
| `name` | 姓名 | 文字 | |
| `alias` | 别称 | 文字，可选 | |
| `role` | 定位 | 枚举 | 用户角色/核心角色/主要配角/次要配角。路人、龙套不建立角色实体（写进指南） |
| `age` | 年龄 | 文字 | 例如「外表十八，实际千岁」 |
| `intro` | 简介 | 文字 | 背景与人设概括 |
| `tags` | 身份 | 文字数组 | 清单上限，见 6.4 |
| `appearance` | 外貌 | 文字 | |
| `condition` | 当前状态 | 文字 | 叙事性描述，例如「疲惫，左臂受伤」。数值类状态放在 `rp.gauges` |

## 4. 角色模块（挂在 `characters.<charId>` 下）

### 4.1 驱动力 `drive`

| 键 | 名称 | 类型 | 剧透 |
| --- | --- | --- | --- |
| `goals.long` / `goals.short` | 远期 / 近期目标 | 文字 | NPC 默认剧透 |
| `thoughts` | 想法 | 文字 | NPC 默认剧透 |
| `plan` | 规划 | `[{ text, done }]`，清单上限 | NPC 默认剧透 |

用户角色的这些字段默认公开。

### 4.2 社交 `relations.<charId>`

键是对方的角色 ID（引用，对方被删除时整条移除）。关系是单向的：A 对 B 的看法记在 A 身上。

| 键 | 名称 | 类型 | 说明 |
| --- | --- | --- | --- |
| `affection` | 好感度 | 整数 −100～100 | 单次变化上限 ±10（6.3） |
| `labels` | 关系 | 文字数组，清单上限 | |
| `impression` | 印象 | 文字 | |
| `promises` | 约定 | 文字数组，清单上限 | |
| `keyEvents` | 关键事件 | `[{ round, text }]`，清单上限 | `round` 由引擎自动填写（6.6） |

### 4.3 角色扮演 `rp`

| 键 | 名称 | 类型 | 子模块 |
| --- | --- | --- | --- |
| `rank` | 位阶 | 文字 | 由操作 LLM 依世界观推断 |
| `attributes` | 属性 | 见 4.4，四种体系互斥 | 属性 |
| `special` | 特殊属性 | 字典 `名称 → 文字或数字` | 属性 |
| `traits` | 特质（被动） | 字典 `名称 → desc` | 能力 |
| `skills` | 技能（主动） | 字典 `名称 → { desc, level? }` | 能力 |
| `gauges` | 量表 | 字典 `名称 → { value, max }` | 状态 |
| `effects` | 效果 | 字典 `名称 → { desc, source?, until? }` | 状态 |

- `gauges` 的名称由模型依世界观决定（生命、体力、法力、理智……），状态栏画成进度条。
- `effects` 不计剩余回合。`until` 是可选的文字条件（例如「直到天亮」），模型判断剧情上结束后移除。

### 4.4 属性体系（互斥组 `attributes`）

四种体系是一个**互斥组**（6.2）：玩家随时切换，同一时间只有一种开启；其余休眠，数据保留，LLM 看不到。所有属性都允许 `null`（空缺）。

| 体系 | 键 | 值 | 状态栏 |
| --- | --- | --- | --- |
| `dnd` | `str dex con int wis cha` | 整数 0～30 或空缺；调整值 ⌊(值−10)/2⌋ 由引擎计算 | 数字 + 调整值小标 |
| `wod` | 生理 `str dex sta`，心智 `int wits res`，互动 `pre man com` | 整数 ≥0，无上限，或空缺；**超凡** = 值≥1 时 ⌊(值−1)/5⌋，由引擎计算，模型可见、不可写 | 数字 + 超凡徽章 + 5 格进度（距下一点超凡） |
| `fate` | `physique athletics melee shoot notice empathy rapport deceive provoke contacts investigate lore crafts burglary stealth drive resources will` | 阶梯 F/F+/E/E+/D/D+/C/C+/B/B+/A/A+/S/S+/EX 或空缺 | 阶梯 |
| `fu` | `might dex insight will` | 弱/普通/优秀/卓越 或空缺（对应原规则 d6/d8/d10/d12，只在提示框显示） | 四格阶梯 |

WOD 兼容「无限恐怖」类规则：中后期一项属性可达几十点，因此只显示数字，不用圆点。超凡示例：5→0，6→1，10→1，11→2。

### 4.5 资产

| 键 | 名称 | 类型 | 说明 |
| --- | --- | --- | --- |
| `items.<itemId>` | 物品 | 实体集合 | 角色之间用 `$move` 转移 |
| ↳ `name` `count` | 物品名、数量 | 文字、整数 ≥0 | |
| ↳ `type` | 类型 | 枚举 | 装备/道具/消耗/关键/杂物/座驾 |
| ↳ `desc` | 描述 | 文字 | 用户视角的描述 |
| ↳ `truth` | 真实描述 | 文字，可选 | 只写与 `desc` 不同之处；默认隐藏 |
| ↳ `equipped` | 已装备 | 布尔 | |
| ↳ `condition` | 状态 | 文字，可选 | 主要给座驾用 |
| `funds` | 资金 | 字典 `货币 → 整数` | 货币种类由模型依世界观定义；转账用 `$transfer` 保证守恒 |

## 5. 根节点模块

### 5.1 地图 `places.<placeId>`（节点地图）

不做网格地图。地点是实体集合，用层级和连通两种关系组成节点图。

| 键 | 名称 | 类型 | 说明 |
| --- | --- | --- | --- |
| `name` | 地点名 | 文字 | |
| `kind` | 类别 | 枚举 | 区域/地点 |
| `parent` | 上级 | 引用 → `places`，可选 | 例：世界 → 王都 → 酒馆 |
| `links` | 相连 | 引用数组 → `places` | 只记相通关系，不需要坐标 |
| `desc` / `truth` | 描述 / 真实描述 | 文字 | `truth` 默认隐藏 |
| `discovered` | 已发现 | 布尔 | 未发现的地点在地图上雾化 |
| `image` / `bgm` | 背景图 / 背景音乐 | 文字（网址或曲库标识），可选 | |

状态栏（电脑与手机都用节点图）：自动排版，当前位置高亮并居中，双指缩放、拖曳平移，点击节点打开详情（手机为底部抽屉）。顶部显示层级路径「王都 › 酒馆」。

### 5.2 不动产 `estates.<estateId>`

| 键 | 名称 | 类型 |
| --- | --- | --- |
| `name` | 名称 | 文字 |
| `owner` | 产权人 | 引用 → `characters` 或 `factions` |
| `place` | 位置 | 引用 → `places`（地图关闭时为文字） |
| `desc` / `truth` | 描述 / 真实描述 | 文字 |
| `developments` | 建设 | 字典 `名称 → 文字` |

### 5.3 势力 `factions.<factionId>`

| 键 | 名称 | 类型 | 说明 |
| --- | --- | --- | --- |
| `name` / `alias` | 势力名 / 别称 | 文字 | |
| `tier` | 定位 | 枚举 | 霸主统治/核心大派/地方霸权/隐秘结社/小型流派；杂鱼团伙不建实体 |
| `leader` | 领袖 | 引用 → `characters`，可选 | |
| `intro` | 概括 | 文字 | |
| `base` | 根据地 | 引用 → `places` | |
| `territory` | 势力范围 | 引用数组 → `places` | |
| `goals.long` / `goals.short` | 目标 | 文字 | 默认剧透 |
| `plan` | 规划 | 文字数组，清单上限 | 默认剧透 |
| `reputation.<charId>` | 声望 | `{ value −100～100, title, keyEvents[{round,text}] }` | `value` 单次变化上限 ±10 |
| `diplomacy.<factionId>` | 外交 | `{ stance, moves }` | stance：盟友/敌对/冷淡中立/臣服依附；`moves` 默认剧透 |

## 6. 需要新增的引擎能力

| # | 能力 | 说明 |
| --- | --- | --- |
| 6.1 | 声明式结构描述 | JSON 描述字段类型、约束、显示名、剧透等级和布局，编译成现有定义（Zod + 实体/引用/模块/指南）。制作面板编辑的就是这份描述 |
| 6.2 | 互斥组与迁移指令 | **通用能力**：任何一组模块都可以声明为互斥。切换时关闭其他成员，数据保留休眠。切换那一次，引擎给操作 LLM 一条一次性迁移指令，附上切出成员的当前数据，要求按新成员的规则换算填写；之后旧数据不再进入提示词 |
| 6.3 | 单次变化上限 | 字段可声明 `maxDelta`，超出时截断并给模型反馈。只作用于声明的字段；官方结构只给好感度和声望设 ±10，玩家可在设置里调整 |
| 6.4 | 清单上限与预警 | 每个会增长的清单有「上限」和「预警线」，玩家在设置里调整（按聊天保存，另有全局默认）。到预警线时，给操作 LLM 的指令自动加上「X 清单已有 n/m 条，请合并相近条目、删除过时内容」；到上限时拒绝新增并反馈 |
| 6.5 | 计算字段 | 由其他字段算出、不存储、模型不可写，但进入投影（WOD 超凡、DND 调整值） |
| 6.6 | 轮次 | `meta.round` = 该次模型回复所在的酒馆楼层号；保险规则：不小于上一提交的轮次 + 1（防止用 `/cut` 删中间楼层后编号回退）。切换回复版本、重新生成不改变轮次。`keyEvents` 等条目的 `round` 在写入时由引擎自动填写 |
| 6.7 | 声明式投影 | 默认规则：在场角色输出全部字段；不在场角色只输出核心字段；社交只输出与用户角色和在场角色有关的条目；地点只输出当前位置、上级路径与相邻地点的全部字段，其余只输出名称 |
| 6.8 | 剧透等级 | 前端能力，按字段读取等级，模型侧不受影响 |
| 6.9 | 背景音乐 | 引擎负责播放。曲库由卡作者附带和玩家自行添加，两者都支持，每首标注情绪。选曲顺序：当前地点 `bgm` → 上级区域 `bgm` → 曲库中符合 `meta.mood` 的曲目。换曲淡入淡出；播放、暂停、音量在状态栏，设置存在玩家本机；浏览器要求首次播放前用户点击一次页面 |

## 8. 渲染标准与前端分工

- **行为**：Radix 无头组件（页签、折叠、进度条、提示框、滚动区等）。
- **样式**：有卡密预设时沿用卡密的皮肤（SOLVE 组件输出相同的 `data-k` / `data-k-part` 钩子，读取 `--k-*` 令牌）；独立运行时用 SOLVE 自带的默认皮肤。SOLVE 不复制卡密预设的代码（卡密预设为 CC BY-NC 4.0，SOLVE 为 AGPL-3.0）。样式钩子不够用时，向卡密预设仓库提 issue。
- **布局**：由结构作者声明（页签、分组、列数、顺序、折叠）。单个字段的控件默认按类型推断，可用 `as` 在固定清单内改写。未写进布局的字段归入「其他」区。
- **不渲染**：结构可声明 `render: false` 整体关闭自动渲染，或在某一区块声明 `render: false` 留出挂载点，由作者自行渲染；SOLVE 照常提供数据和接口。

前端分三部分：按结构渲染的状态栏、调试面板、结构制作与修改面板。现有调试工作台将整体重做。实现前先出风格与布局预览，经用户确认后再实施。

## 10. 决定记录

- 2026-11-08 用户确认：官方结构面向玩家；键名英文；核心不可关闭（meta 与角色核心）；驱动力、社交为独立模块；角色扮演模块含属性、能力（特质/技能）、状态（量表/效果）；属性四种体系（DND/WOD/FATE/FU）互斥、玩家可随时切换；WOD 无上限并有超凡属性；FU 改为四档文字；属性下限 0、可空缺；座驾并入物品；不动产、势力、地图在根节点；只做节点地图，手机也用节点图；轮次读酒馆楼层；效果不计回合；单次变化上限按字段声明；清单上限由玩家设置并带压缩预警；投影声明式；NSFW 不加额外约束；年龄为文字；背景音乐由引擎负责，曲库可由卡作者附带或玩家添加；迁移指令泛化为所有互斥组的能力。
