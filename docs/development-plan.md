# SOLVE 后续开发计划（实施中）

更新日期：2026-10-26。原始基线：后端 0.5.0；当前基线为 0.8.3、格式 3、113 项自动检查（变量引擎与调试面板，AGPL-3.0-only 授权）。本轮开始执行 [边界验收与交付计划](acceptance-release-plan.md)，保持 JSON Patch 单一变更格式。

用户已确认开始实施，前端缩为功能全面的调试面板；明确使用 React + Radix，要求美观、高级、简洁、易用，同时适配电脑和手机。最新授权“不用向我确认布局了，直接开始吧”。已采用松绿＋暖灰，设计见 [frontend-design.md](frontend-design.md)。当前已实现内容和验证边界见 [当前交付](implementation-status.md)，调试程序接口见 [debug-api.md](debug-api.md)。

本文根据现有企划、实施规范、源码、测试和已保存的实测记录整理。阶段顺序和版本号是建议，未替代已确认的产品范围。

## 1. 当前判断

项目已有变量引擎、酒馆适配器与调试界面。后续重点是用真实角色卡验收完整聊天流程，再降低作者接入成本，推进更完整的制作工具。

| 范围 | 当前情况 | 证据与边界 |
|---|---|---|
| 核心执行 | 十个原算子、`$group`、实体引用、模块、双格式投影已实现 | `src/engine.ts`、`src/entities.ts`、`src/schema.ts`、`src/projection.ts`；自动测试通过 |
| 历史与保存 | 已实现按回复版本保存、失败草稿、恢复和重放 | `src/history.ts`、`src/runtime.ts`；已有真实服务端保存/回读记录 |
| 酒馆接入 | 三种分发入口与双模型模式已实现 | `src/extension.ts`、`src/dynamic.ts`、`src/host/`；三载体真实回复、保存、恢复已验收，其余事件边界见验证记录 |
| 作者入口 | 目前采用分离式 JS/TS 定义，提供一个 RPG 示例 | `src/types.ts`、`examples/rpg-definition.ts`；需要作者脚本调用 `SOLVE.attach()` |
| 自动加载 | 已有定义注册、明确角色绑定、自动会话切换和过期绑定检查 | `src/host/sessions.ts`、`src/extension.ts`；作者脚本需在页面加载时注册 |

规划阶段检查为 71 项测试。0.6 实施后扩充到 85 项，0.7 增加到 90 项，0.8.0 增加到 96 项，0.8.3 已达到 **113 项**；最终结果以 `docs/verification.md` 和命令输出为准。

已有的 `test-results/host-1.19.json` 记录宿主 1.19.0、passed=true、cleanup=true。该脚本连接真实服务端，但在 Node 中构造宿主上下文，不能据此认定页面里的生成事件、宏、渲染和连接预设已经完整实测。

最初规划阶段的 DSH 核查因 SERVER 错误未完成，未计为通过。0.6 实施阶段沿用同一 DSH 会话，以 agent2api / deepseek-v4.1-flash / max 完成两轮公开审查；结论已由主代理核实并转为修复与回归测试。

## 2. 第一阶段：补齐 0.5 的宿主验证与恢复流程

**目标：** 明确哪些使用场景已经可靠，修复阻止恢复或继续聊天的问题。建议作为 0.5.x 的收尾工作。

优先任务：

1. 建立宿主能力清单：实际版本、生成事件、宏注册、渲染钩子、原生请求拦截、连接预设服务、浏览器写锁与 IndexedDB。缺少关键能力时给出明确原因。
2. 在真实浏览器中验证：普通回复、流式回复、停止生成、重新生成、切换回复版本、切换聊天、编辑和删除楼层、创建分支、刷新后恢复。
3. 验证独立操作模型的成功、超时、取消、迟到响应及重复结束信号。先用可控测试响应排除模型输出波动；真实连接预设请求另列证据，不能用模拟请求代替。
4. 注入保存失败、保存成功但响应丢失、两个标签页交替保存，核对重试不会重复执行，过期结果不会写入其他聊天或回复版本。
5. 增补上述场景的有效回归测试，记录宿主实际版本、操作步骤、结果和不支持的入口。

**验收：** 每项都能说明“从哪里开始、执行什么、应得到什么状态”；核对正文操作块、当前提交与落盘记录一致。需要重放时明确阻止错误接续；错误处理后有可执行的恢复路径。

所有宿主测试继续使用独立临时角色和聊天。已有服务端测试保留；浏览器测试补充页面行为的证据。

**涉及位置：** `src/host/controller.ts`、`src/host/sillytavern.ts`、`src/extension.ts`、`tests/controller.test.ts`、`tests/host.test.ts`、`scripts/`、`docs/verification.md`。

## 3. 第二阶段：完善加载、会话管理与草稿恢复

**目标：** 作者按文档接入后，刷新和切聊天可以正常恢复，常见操作无需反复手动解绑。建议版本 0.6。

优先任务：

1. 增加作者定义注册与解析入口，记录定义 ID、版本和指纹。旧聊天继续使用原定义；缺失或不匹配时给出明确诊断，不静默套用新版规则。
2. 管理绑定生命周期：等待扩展和作者包就绪、创建新会话、恢复已有会话、切聊天取消旧任务、释放监听与宏、重新绑定。只处理明确注册或绑定的角色卡。
3. 在标准浏览器接入中默认启用缓存，并提供关闭方式。缓存不可用时仍可从聊天恢复，同时报告草稿是否能跨刷新保留。
4. 提供控制器级“查看待保存操作、重试、放弃”入口。重试复用原结果；放弃时同步清理内存和本地草稿，不能刷新后再次出现。
5. 将经过校验的缓存恢复接入 Runtime，并补充命中、失效和故障回退测试；仍保留聊天归档的损坏检测。
6. 补全从安装、加载示例、发送消息到刷新恢复的作者入门说明，包括独立操作模型的配置方法。

**验收：** 同一卡的两个聊天分别保留状态；连续切换后没有重复监听或重复执行；刷新能恢复正式状态与待保存草稿；缺少原定义时可以检查已归档事实，并明确哪些写入和重放能力不可用。

**涉及位置：** `src/extension.ts`、`src/host/controller.ts`、`src/runtime.ts`、`src/cache.ts`、`src/types.ts`，以及新增的定义注册/会话管理模块与对应测试。

## 4. 第三阶段：统一读取与诊断接口，再做 Inspector

**目标：** 作者和玩家能看懂当前状态、保存结果及失败原因。建议版本 0.7；先做不依赖页面设计的接口。

接口工作：

- 统一状态读取、单值读取、投影读取和订阅入口。读取返回安全拷贝，所有状态修改继续经过动作提交。
- 提供聊天/消息/回复版本身份、当前提交、就绪原因、忙碌状态、待保存状态、缓存状态和最近错误。
- 区分“操作不合法”“还没保存”“历史链需要重放”“归档损坏”。订阅事件要说明结果是否已成功归档。
- 对外提供重放和草稿处理方法，避免界面直接访问内部对象。

Inspector 候选范围：状态与实体定位、操作与变更记录、模型上下文预览、历史和保存诊断。先实现必要的检查与恢复操作，再评估完整状态编辑。

**前端授权：** 用户已明确无需继续确认布局，直接开始实施。设计文档已记录当前方向，正式调试面板已实现并进行浏览器验证。

**验收：** 不打开开发者控制台也能判断状态是否已保存、失败原因和下一步操作；界面触发的修改均能归档与恢复；不会把未保存候选显示成正式历史。

## 5. 第四阶段：完善作者制作体系

**目标：** 作者可以在结构定义旁或世界书中维护规则，减少重复配置。建议版本 0.8；每个入口都复用现有引擎。

推荐拆分顺序：

1. 明确声明数据与执行函数的绑定契约；沿用作者定义版本，逐步补充构建指纹和依赖信息。
2. 世界书 `[SOLVE:...]` 条目解析与来源诊断。结构、开局、模板和预制在会话建立时固定；指南按已确认规则选择和更新。
3. 完成六板块统一收集流程，以及 Facet 的最小扩展接口；再补内联声明和多文件组合，避免同时维护多套语义。
4. 验证原生扩展、作者脚本和助手/iframe 载体的共存、就绪握手与单会话所有权。分别记录请求拦截覆盖范围。
5. 增加至少三类完整示例：简单人物属性、带购买原子组的背包、带模块与引用关系的复杂卡。附作者常见错误和修正方法。

**验收：** 同一份业务定义从不同作者入口产生相同状态结果；旧聊天不因世界书结构更新而改变；首次接入者按照文档即可完成示例，并能在诊断工具中找到配置问题。

## 6. 性能工作：尽早测量，按结果优化

第一阶段同步准备基准数据，后续每个重要改动保留对比。发布 1.0 前完成规模验收。

沿用企划的 S/M/L/XL 档位：约 10 KB、100 KB、1 MB、5 MB；历史长度分别测试 100、1,000、5,000 楼。记录浏览器和设备环境，并分别测量：

- 单条与批量操作、group 成功与回退、实体移动与删除。
- 冷恢复、缓存恢复、回复版本切换和历史重放。
- 保存前计算与真实保存回读耗时，避免混成一个数字。
- 文件大小、内存峰值、页面卡顿，以及不同投影和格式的文本大小。

源码中值得优先测量的位置：

| 位置 | 当前行为 | 后续判断依据 |
|---|---|---|
| `src/engine.ts:114`、`src/schema.ts:150` | 每条候选操作复制状态并校验，执行中多次重建实体图 | 测量批量指令随状态/实体数量增长的耗时 |
| `src/entities.ts` | 已优化实体拥有关系索引，仍需大规模浏览器数据 | 测量大量实体和深层嵌套时的构图成本 |
| `src/history.ts`、`src/host/controller.ts` | 默认缓存恢复已接入，失效时从开局沿父链恢复 | 比较长历史冷恢复、缓存恢复和每次提交开销 |
| `src/runtime.ts:17` | 读取 archive 会复制整份内存归档 | 测量控制器和宏多次读取时的历史长度影响 |
| `src/cache.ts:31` | 每次写快照前重新验证历史；尚无容量淘汰机制 | 测量写快照成本、配额和快照保留策略 |

这些是待测热点，不是已证实的性能故障。先保留正确性基线，再考虑减少重复复制、重用索引、按需快照和缓存淘汰。跨字段作者规则无法判断依赖时仍需完整校验。

已有格式实验支持继续保留 TOON/紧凑 JSON 的作者选择，并优先改进投影。现阶段继续使用 TypeScript；只有正式基准显示需要时再评估 WASM。

## 7. 1.0 发布检查

- 第一阶段的真实浏览器场景和当前自动检查通过，有可复核记录。
- 六板块作者能力、约定的分发载体及 Inspector 达到主企划的 V1 范围；如果调整范围，先更新产品决定。
- 清缓存、复制聊天、保留多个回复版本后仍能恢复相同状态；损坏归档有明确诊断。
- 作者版本绑定、草稿恢复、独立模型取消和多标签页冲突均有验收。
- 性能报告明确常规支持规模与极限退化情况，发布包能从干净依赖安装重复构建。
- 安装说明、示例、版本记录、兼容范围和已知限制与实际实现一致。

蓝图工作台、可视化状态栏构建器和复杂查询继续按主企划放在后续版本；群聊、运行中更换数据结构和 Rust/WASM 重写不进入当前优先任务。
