## 性能样例

环境：Windows x64，Node v22.19.0；人工构造数据。以下为中位耗时，不是所有角色卡的保证。

| 场景 | 约 9 KB / 50 实体 | 约 94 KB / 500 实体 |
|---|---:|---:|
| 一条增加操作 | 1.08 ms | 7.21 ms |
| 10 条操作组成 group | 5.48 ms | 49.12 ms |
| 单实体 JSON 投影 | 0.07 ms | 0.54 ms |
| 100 楼冷恢复 | 45.66 ms | 314.92 ms |

同一基准把实体索引替换为基线版本单独运行时，500 实体的一条操作约 34.42 ms、10 条 group 约 303.29 ms。优化结果保留原状态语义和所有校验。冷恢复的成本仍随历史长度增长，后续需要真实浏览器、长历史及 L/XL 验收。

运行 `npm run benchmark`，结果写入 `test-results/performance.json`；对照记录为 `test-results/performance-before-index.json`。文本格式只记录字节数，不将其当作 token 数。

## React + Radix 调试面板

用户已明确“不用向我确认布局了，直接开始吧”，因此直接推进设计和实现。设计文档为 [frontend-design.md](frontend-design.md)，采用松绿＋暖灰、系统字体与等宽代码字体，含浅色/深色和电脑/手机布局，无外部图片或生图。

已实现五个工作区：状态/实体/引用/模块与定义、操作预演与提交、历史对比和恢复、上下文多格式预览、诊断与本地导出。支持编辑使预演失效、聊天切换隔离、待保存草稿重试/放弃、忙碌禁写、无定义只读检查。状态树按展开加载，并分批显示大量条目。

原生扩展以同源 iframe 隔离样式，提供右下角 SOLVE 入口；使用原生模态层处理背景焦点，Radix 处理面板内 Tabs、Switch、Dialog 和 AlertDialog。独立演示使用真实引擎/控制器与内存宿主，刷新重置、不调用模型。浏览器已实际验证预演、过期阻止、保存/失败重试、路径读取、历史差异/归档校验、上下文、手机宽度、同源嵌入与只读检查；详细记录见 verification.md。
